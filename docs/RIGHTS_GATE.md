# 利用権限の監査とキルスイッチ（Issue #3）

データを扱う境界（取り込み・学習・公開）は、必ず `keirin_intelligence.rights.RightsGate` を通します。
判断はすべて改ざん検知つきの監査ログ（ハッシュ連鎖の JSONL）に残り、拒否理由を後から確認できます。
法的助言ではありません。許諾の有無は書面で確認し、Issue #2 に記録してください。

## 記録する出典情報（`Provenance`）

| 項目 | 意味 |
|---|---|
| `source_id` | 提供元。`data/reference/rights_registry.csv` の行と一致させる |
| `contract_id` | そのレコードを取得したときの契約番号（書面の参照） |
| `observed_at` | 提供元で事実が公表・観測された時刻 |
| `ingested_at` | 当方のストアに入った時刻 |
| `raw_sha256` | 元ファイルのハッシュ |
| `synthetic` | 架空データかどうか |

## 判断のルール（上から順に、最初に当てはまったものが理由になる）

1. `observed_at` か `ingested_at` が判断時刻より後 → 拒否（先読み）。研究用途でも拒否します。
2. 研究用途（`Purpose.RESEARCH`）→ 許可。販売・公開には使えません。
3. 商用キルスイッチが入っている → 拒否。
4. 架空データ → 拒否。
5. 台帳にない提供元、`approved` 以外、失効、撤回、契約番号なし、契約番号の不一致 → 拒否。
6. 用途に必要な許可（保存 / 学習 / 派生物の販売）が欠けている → 拒否。

用途ごとに必要な許可: 取り込み＝保存、学習＝保存＋学習、公開＝保存＋学習＋派生物の販売。

## 台帳の更新と再評価

- 許諾が書面で得られたら `rights_registry.csv` の行を `approved` にし、契約番号・各許可・失効日を記入して PR でレビューします。
- 契約の変更・失効・撤回があったら、同じ CSV を更新し（撤回は `revoked_at` を記入）、すぐに次を実行します。

```bash
keirin rights-review --audit data/audit/rights.jsonl
```

過去に商用で許可した判断のうち、今は許可されないものを一覧にして、1件でもあれば終了コード1で終わります。
定期実行（日次）にも組み込みます。

## 停止手順

1. **すぐ止める**: `KEIRIN_COMMERCIAL_KILL_SWITCH=1` を設定するか、リポジトリ直下に `KILL_SWITCH` ファイルを置きます。以後の商用の判断はすべて拒否されます（研究用途は継続）。
2. `keirin rights-review` で影響する提供元と用途を特定します。
3. 該当提供元のデータで学習したモデルと、それを使った記事を停止します（公開済みの記事は訂正を追記で出し、元の記録は消しません）。
4. 契約に削除義務があれば、取り込み済みデータと原本を削除し、その記録を残します。
5. 原因と対応を Issue に残してから、キルスイッチを外します。
